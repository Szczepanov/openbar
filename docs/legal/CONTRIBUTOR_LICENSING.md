# Contributor licensing policy

## Current rule

Until a professionally reviewed CLA or equivalent contributor-rights process is adopted, maintainers should not merge external substantive code contributions.

Issues, discussions, bug reports, reproducible test cases, and design feedback can still be accepted.

## Why

The project may later need to:

- dual-license code;
- offer commercial licences;
- restructure the ownership entity;
- distribute official paid features;
- change the licence for future versions.

A contribution process should preserve those options while being explicit and fair to contributors.

## Intended properties of the future CLA

The contributor should retain copyright while granting the project owner sufficiently broad, perpetual rights to use, modify, distribute, sublicense/relicense, and commercially exploit the contribution.

The exact legal text must be reviewed for the applicable jurisdiction before adoption.

## Automation

Once approved:

- add the CLA text/policy to the repository;
- configure a CLA bot or equivalent check;
- require CLA status before merging external PRs;
- document exceptions for trivial contributions if counsel recommends them.
