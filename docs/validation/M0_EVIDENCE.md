# M0 Evidence Package

Issue: #14

## Purpose

This is the first reproducible M0 evidence package. It is engineering evidence, not a scientific or
marketing accuracy claim.

The package is generated by:

    python3 validation/tools/m0_evidence.py --output-dir target/m0-evidence

The runner orchestrates the existing Rust CLI. It does not duplicate tracker, calibration,
filtering, kinematic, or benchmark calculations in Python.

## Frozen evaluation configuration

For the current public subset:

- evaluate both retained tracker baselines: template-sad-v1 and local-contrast-centroid-v1;
- do not declare a production tracker winner;
- use template-sad-v1 + raw-identity@1 only as the canonical end-to-end integration probe;
- use the fixture's 0.45 m plate diameter;
- use backward-difference@1 kinematics with max continuity gap 0.2 s;
- use benchmark timestamp tolerance 0.0005 s and minimum confidence 0.0;
- preserve tracker-declared loss rather than treating it as coordinate error.

The filter production choice remains deferred pending real annotated data.

## Current public dataset

The redistribution-safe fixture manifest currently contains one synthetic clean fixture:

- role: development;
- nominal/measured frame rate: 12 fps;
- camera: fixed side view;
- motion blur: none;
- occlusion: visible, partially occluded, and one fully occluded unlabelable frame;
- comparable labelled samples: 10;
- no held-out validation fixture;
- no public snatch or back-squat fixture.

The synthetic annotation repeatability artifact records 10 matching labelled timestamps, mean
Euclidean disagreement 0.9 px, RMSE 0.948683 px, and maximum disagreement 1.0 px.

These facts make the public subset useful for reproducibility, schema/contract regression, tracker
failure inspection, and deterministic integration testing. They do not make it representative of
ordinary phone lifting video.

## Evidence generated

Each run produces:

- two complete decoded-video tracker runs so normalized prediction streams can be compared;
- benchmark output for both retained tracker baselines against the same annotations;
- X/Y and combined centre MAE/RMSE;
- case-level radial error p50/p90/p95/max;
- availability/loss and maximum consecutive loss;
- repeated benchmark evaluation to verify deterministic numeric output;
- two canonical analyze runs to verify byte-identical deterministic analysis output;
- filter-experiment evidence;
- diagnostic success and loss/low-confidence SVGs;
- environment and runtime provenance;
- an explicit status for every provisional M0 gate;
- a generated human-readable M0_EVIDENCE_REPORT.md.

The complete machine-readable aggregate is m0-evidence-v1.json and is validated by
validation/schema/m0-evidence-v1.schema.json. The deterministic public-subset report is committed as
[M0_EVIDENCE_REPORT.md](M0_EVIDENCE_REPORT.md); CI regenerates it and fails on drift.

## Gate interpretation

| Metric | Initial target | Current status |
| --- | ---: | --- |
| Plate-centre tracking MAE | < 3 px | NOT MEASURABLE YET |
| Tracking availability in supported clips | > 99% | NOT MEASURABLE YET |
| Range-of-motion MAE | < 0.01 m | NOT MEASURABLE YET |
| Mean velocity MAE | < 0.05 m/s | NOT MEASURABLE YET |
| Peak velocity MAE | < 0.10 m/s | NOT MEASURABLE YET |
| Repeat-analysis determinism | 100% | evaluated by each evidence run |
| Offline processing | faster than video duration on reference hardware | NOT MEASURABLE YET |

The first five performance/accuracy gates stay NOT MEASURABLE YET even if the synthetic fixture
numerically falls inside a threshold. There is only one development fixture, no held-out real-video
set, and no independent physical ROM/velocity reference.

The determinism gate is allowed to PASS for the evaluated public subset when repeated normalized
tracker predictions, repeated benchmark outputs, and repeated canonical analysis are identical. Its
scope must remain explicit.

The runtime gate stays NOT MEASURABLE YET until the project designates stable reference hardware and
uses representative clips. Per-run timing is still retained as diagnostic evidence.

## Subgroup reporting

Issue #14 asks for lift, FPS, framing/distance, blur, occlusion, camera movement, contrast, yaw, and
development/held-out breakdowns where data supports them.

The current public subset supports only a single clean / 12 fps / fixed-side / development
condition. Sample counts therefore accompany every generated result and unsupported subgroups are
reported as missing rather than converted into conclusions.

## Ground truth and validity limits

Tracker reference is manual centre digitisation of a first-principles synthetic video. The public
subset has no independent physical displacement/ROM reference and no definition-matched
VBT/encoder/reference velocity source.

Mean concentric velocity must not be inferred from whole-clip mean-axis velocity. Peak Euclidean
speed from the filter experiment must not be relabelled as signed vertical peak velocity.

The package intentionally preserves failed and unavailable evidence. A gate is never omitted merely
because the current repository cannot measure it.

## Next evidence required

Before the currently unavailable performance gates can be resolved:

1. add redistribution-safe or locally reproducible real clean, snatch, and back-squat fixtures;
2. establish development versus held-out validation roles;
3. cover realistic frame rates, framing/distance, blur, camera motion, contrast, occlusion and yaw;
4. add independent calibrated position/ROM reference;
5. add definition- and phase-matched velocity reference;
6. designate reference hardware for the offline-speed gate;
7. rerun the same evidence package without changing gate semantics merely to improve headline results.
